# PRD 与金融工程技术方案语言表达规范

本文档为 Prism 项目全局技术文档、方案设计与对外表达的唯一语言与格式基准。后续所有技术方案、PRD 交互定义、功能梳理与汇报文档必须严格遵循本规范。

---

## 一、 语气基调与文风原则

1. **严肃客观，杜绝口语与修饰词**：
   - 全文采用极度客观、克制、严密的工程学术与金融技术语言；
   - 严禁使用任何表情符号（Emoji）；
   - 严禁出现“四轨道研发矩阵与证据链溯源底座”等华而不实、超长修饰词堆砌的营销口号；
   - 严禁出现口语化过渡句（如“咱们来看看”、“接下来搞定这个”等）。

2. **概念严谨，边界清晰**：
   - 严格区分**业务角色（Persona）**与**投资者画像（Profile）**：业务角色决定界面入口、功能分流与交互解释深度；投资者画像决定底层数学约束、合规边界与资产求解算法；
   - 严格区分**大模型认知理解（LLM）**与**确定性金融计算（Deterministic Engine）**：LLM 仅作为自然语言意图理解、槽位抽取与通俗化转述的辅助工具，严禁介入任何金融算术、敞口穿透与调仓比例计算；
   - 明确**独立合规与风控硬闸门**的物理隔离地位，不可与业务逻辑混淆。

---

## 二、 结构与排版范式

1. **分级编号标准**：
   - 统一采用标准技术公文层级：`## 第X章 ...` ➔ `### 一、 ...` ➔ `1. ...` ➔ `* ...`；
   - 章节标题简洁明确，直指业务目标与技术载体。

2. **高密度表格优先（Tabular First）**：
   - 凡涉及痛点对比、状态机流转、角色分层、指标阈值、疑点类型、延迟预算、接口清单等场景，必须优先使用 4~5 栏 Markdown 结构化表格；
   - 表头清晰，内容精炼，重点字段加粗，数据附带单位。

3. **Mermaid 拓扑与流程图辅助**：
   - 架构分层、状态机跃迁、资产穿透计算、再平衡流转必须配备标准的 Mermaid 流程图（`flowchart TD` / `flowchart LR`）；
   - 图中节点文案精简，严禁超长文本。

---

## 三、 金融量化与工程规范

1. **量化指标严密化与容差量化**：
   - 涉及指标必须提供数学计算式与明确阈值（如：报价容差 $\le 0.1\%$、财报容差 $\le 1.0\%$、集中度 $\le 30.0\%$、换手率死区 $\le 20.0\%$、P95 延迟 $\le 3.0\text{s}$）；
   - 所有百分比、金额、系数计算采用 Decimal 确定性高精度算法，保持总权重 $100\%$ 守恒。

2. **组件复用与开源选型**：
   - 坚决杜绝低水平重复造轮子（如拒绝从零自研 Canvas/SVG 连线引擎）；
   - 复杂图形编排直接选型工业级成熟开源方案（如 AntV X6 / LiteGraph / Flow）。

---

## 四、 前端交互与状态呈现标准

1. **Codeforces 风格裁决标签体系**：
   - 状态标识采用高密度紧凑标签：`PASS 合规通过`、`OVERBOUND 风险拦截`、`CALCULATED 测算完成`，统一等宽字体与纯色底边框。

2. **菜鸟教程 / 技术文档标准 Callout 提示块**：
   - 统一采用左侧强调边条 + 极浅背景的信息块：
     - `Tip`（提示 / 绿色微青）：合规通过建议与基础观察；
     - `Warning`（注意 / 暖黄橙色）：参数临界与潜在波动；
     - `Danger`（风险 / 绯红）：隐性集中度超标与画像硬约束阻断；
     - `Info`（规则 / 蓝灰）：基本面研判与数据来源说明；
     - `Demo`（操作 / 翠绿）：调仓执行步骤与准则指导。
