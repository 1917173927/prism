# 附加分析页面渐进式披露

## 目标与范围

按已确认的九页 HTML 预览调整生产页面，修复跨页面账户设置弹窗，保留公共导航与现有后端计算。完成真实验证及 subagent 审核后提交并推送。

## 页面设计

| 页面 | 默认内容 | 按需内容 | 接口边界 |
| --- | --- | --- | --- |
| 组合优化 | 一个生成入口、结果摘要 | 调整范围、权重变化、调整依据 | 复用真实持仓优化接口 |
| 调仓方案 | 一个生成入口、结果状态 | 买卖清单、资金与换手、执行顺序 | 复用现有调仓接口 |
| 市场变化模拟 | 单行业与幅度、计算入口、损益摘要 | 多行业参数、风险指标、计算依据 | 复用五行业确定性接口 |
| 三类证券研究 | 运行入口、研究状态 | 指标、风险、来源 | 保留既有服务与 LIVE 能力限制 |
| 持仓明细 | 标的、数量、市值、占比 | 成本盈亏、基金穿透 | 读取当前持仓与正式报告 |
| 历史建议 | 记录列表、刷新入口 | 单条记录内容、开发者比较 | 不增加后端未支持的过滤条件 |
| 分析依据 | 计算入口、风险检查摘要 | 计算过程、行业边界、复查条件 | 读取真实持仓体检结果 |

## 实施选择

账户设置可使用全局原生 dialog 或全局 div 弹窗。采用原生 dialog，与现有导入及详情窗口一致，提供浏览器焦点管理和 Escape 关闭。

结果组织可保留全部结果并增加折叠容器，或分别重建每组结果。采用明确分组的原生 details，保留现有挂载 ID、数据字段和计算调用，默认显示摘要及失败原因。

市场变化模拟采用显式计算按钮。单行业与多行业共享五个参数，编辑时使旧结果失效，切换编辑方式保持参数一致。预设情景保留在开发者工具中。

## 验证安排

使用隔离数据库运行正常认证服务，业务请求连接真实后端。复验九个页面、五个主页面的账户设置、输入同步、空状态与失败状态；检查持仓结果、优化、调仓、市场变化模拟的真实响应。运行相关回归、JavaScript 语法及差异格式检查。浏览器操作采用 CUA，证据保存在忽略目录 output/auxiliary-disclosure-verification。

## 验证结果

正常账户完成问卷确认和五项演示持仓的真实文字导入，组合优化、调仓、市场变化模拟与持仓体检均收到后端结果。持仓表中的五项证券占比与正式报告一致，现金单独展示；分析依据显示后端返回的行业超限，并按需展示中文计算过程。

九个页面的默认分组、统一导航与键盘折叠通过检查；账户设置在五个主页面可见，Escape 关闭和焦点恢复正常，保存后重新打开可读取当前设置。三类证券研究的实际接口失败显示本页提示并恢复按钮。320、390、768、1440px 的九页检查通过，页面没有横向溢出，浏览器没有 JavaScript 错误。

相关界面与正式报告检查共 28 项通过；JavaScript 语法和 Git 差异格式检查通过。浏览器流程由 `tests/browser/test_auxiliary_disclosure.mjs` 通过 CUA 执行，记录见 `output/auxiliary-disclosure-verification/browser-evidence.json`，正式报告响应见同目录 `api-evidence.json`。

第二轮审核确认九个附加页面、统一导航、默认折叠、参数同步、失败恢复和响应式布局保持通过。调仓页面在前置组合优化期间保存画像时，会依据入口 `contextRevision` 放弃旧请求；组合优化结果中的权重字段、风险等级及个股研究快速阶段文案已经中文化并删除重复防御性说明。新增回归检查覆盖上下文版本守护和附加结果文案。
