# 真实数据接入后的用户流程缺陷修复

## 范围与约束

- 仅修复现有功能的可复现缺陷，不新增业务能力。
- 保留原有 README.md 与 docs/prd-integration-guide.md 未提交内容。
- 真实数据缺失、请求失败与合成示例保持明确区分；风险画像与金融计算由后端确定性服务裁决。
- 使用独立本地服务的内存数据库体验问卷、持仓、体检、研究、调仓和模式切换，避免污染当前用户服务状态。

## 排查与方案

| 环节 | 已验证事实 | 待验证问题 | 处理原则 |
| --- | --- | --- | --- |
| 基线 | 557 项测试通过；8000 端口 LIVE 扶摇行情成功 | 页面流程覆盖不足 | 增加针对根因的行为回归 |
| 首次使用 | 问卷未完成时首页持续计算中，体检报无后端结果 | 画像、持仓前置条件未正确呈现 | 显式引导既有问卷与持仓入口 |
| 数据消费 | 真实行情缺少财务指标 | 空值、资产类型、时间与模式切换的一致性 | 缺失不转零，不补造数据 |
| 后续操作 | 待体验 | 研究、体检、调仓及失败恢复 | 对原路径复测 |

方案比较：可以重构统一任务编排，也可以修复现有前置检查、数据映射与请求生命周期。选择后者，改动范围较小，保留现有接口与交互结构；仅在重复根因需要时复用已有辅助函数。
